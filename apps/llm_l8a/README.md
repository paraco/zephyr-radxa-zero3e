# L8a — 왜 느린가 (측정만, 판정 없음)

L6c 가 실기에서 **토큰당 23.6초**를 냈다. 가중치 497.39 MiB 를 매 토큰
읽으므로 유효 처리율이 **21.1 MiB/s** 다. A55 한 코어로 0.8B Q4 는 보통
1~4 tok/s 이니 우리는 **25~100배 느리다** — "한 코어라서" 로는 설명되지 않는다.

성능 플래그(repack · `-ffp-contract=fast` · 멀티코어)를 뒤집기 **전에**
원인을 재는 칸이다. 원인이 메모리면 플래그는 아무 효과가 없다.

⚠ 이 칸은 **판정하지 않는다.** 기준값을 모르는 상태에서 PASS/FAIL 을 매기면
그 기준이 곧 추측이 된다.

## ✅ 실기 측정 — 2026-11-07

```
[1] CPU·캐시 상태
    MIDR      0x412fd050            (Cortex-A55 r2p0)
    SCTLR_EL1 0x0000000030d0180d
      M(MMU)=1  C(D캐시)=1  I(I캐시)=1
    CTR_EL0   0x84448004  (D줄 64 B · I줄 64 B)
    CNTFRQ    24000000 Hz
    CPU 수    1 (CONFIG_MP_MAX_NUM_CPUS)
[2] 계산 루프 5천만 반복 ... 1616 ms (61 Mops/s)
[3] sram0(힙) 읽기 32 MiB ... 695 MiB/s · 2회차 711 MiB/s
[4] 모델 창 읽기 32 MiB ..... 695 MiB/s
```

## 내 가설이 깨졌다

| 가설 | 결과 |
|---|---|
| D캐시가 꺼져 있다 | ❌ `SCTLR_EL1` 의 **C=1 · I=1 · M=1** |
| 모델 창의 MMU 속성이 틀렸다 (`zephyr,memory-attr` 가 안 먹었다) | ⚠ **이 비교로는 가릴 수 없었다** — 아래 "내가 틀린 곳" |

CRC32 11.8 MiB/s 를 "캐시가 안 먹는다" 로 읽었는데 **틀렸다.** 695 MiB/s 로
읽히는 메모리다. CRC32 가 느린 것은 **바이트 단위 테이블 조회** 자체가
느린 것이고(의존 사슬 + 1바이트씩), 그것은 **CPU 가 느리면** 그대로 느려진다.

## 남은 단서 — `[2]` 계산 루프

의존 곱 사슬(`a = a*K1 + K2; b ^= a >> 17`)은 A55 에서 반복당 약 4~5
사이클이다. 5천만 반복 = 2억~2.5억 사이클인데 **1.616초**가 걸렸다.
→ **CPU 가 약 120~155 MHz** 로 보인다. 이 SoC 의 A55 는 **1.8 GHz** 다.

짚이는 것: RK3566 은 U-Boot 가 보수적인 저주파로 두고 **리눅스의 cpufreq 가
1.8 GHz 로 올린다.** Zephyr 에는 이 SoC 용 CPU 클럭 드라이버가 없으니
**부트로더 기본값 그대로** 돌 것이다.

⚠ 그러나 이것은 **내 사이클 추정에 의존한 결론**이다. 추정을 빼고 재는 것이
`apps/llm_l8b` 다 — PMU 사이클 카운터(`PMCCNTR_EL0`)와 24 MHz arch 타이머를
같이 읽으면 주파수가 직접 나온다.

## 측정에서 실수한 것

`256 KiB 반복 (L2 안) 0 MiB/s` — 0 이 아니라 **못 쟀다.**
`k_uptime_get()` 은 ms 해상도라 256 KiB 읽기(<1 ms)가 0 ms 로 나왔다.
L8b 는 arch 타이머(41.7 ns)로 잰다.

---

## ⚠ 내가 틀린 곳 (L8b 가 드러냈다)

위에서 "모델 창 695 MiB/s = sram0 695 MiB/s, 같으니 속성 문제가 아니다" 로
결론 냈다. **그 추론이 틀렸다.**

**32 MiB 한 점으로는 캐시 여부를 구분할 수 없다.** 32 MiB 는 L2(512 KiB)를
한참 넘는 스트리밍이라, 캐시가 먹든 안 먹든 DRAM 대역에 묶인다. 두 값이
같았던 것은 "둘 다 정상" 이 아니라 **"그 크기에서는 차이가 안 난다"** 였다.

L8b 가 모델 창에 **크기를 바꿔** 재니 이렇게 나왔다:

```
32 KiB (L1)    827 MiB/s
256 KiB (L2)   729 MiB/s
4 MiB          708 MiB/s
32 MiB         706 MiB/s     ← 거의 평평하다
```

815 MHz A55 에서 L1 상주 데이터는 **수 GiB/s** 가 나와야 한다.
827 MiB/s 는 8바이트 적재당 **7.9 사이클**이다(L1 이면 1~2).
**크기를 바꿔도 평평한 것은 캐시가 안 먹는 메모리의 특징이다.**

→ 원래 가설(모델 창의 `zephyr,memory-attr` 가 안 먹었다)이 **되살아났다.**
  가리는 방법은 **같은 크기 쓸기를 sram0 에도** 하는 것이다 — `apps/llm_l8c`.

**교훈:** 비교를 할 때 **그 비교가 가설을 구분할 수 있는지** 먼저 따진다.
한 점으로 두 가설을 가를 수 없으면 그 측정은 가설을 지우지 못한다.
