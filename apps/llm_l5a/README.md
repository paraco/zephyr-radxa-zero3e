# L5a — Gated DeltaNet 층 관문 (합성 가중치)

[docs/llm-hub-test-plan.md](../../docs/llm-hub-test-plan.md) 의 사다리 L5a.
하위 다섯 개를 한 번에 본다. 치수는 Qwen3.5-0.8B 의 **실측값**이다
(`S=128 H=16 d_conv=4 conv_dim=6144 n_embd=1024`).

## ⚠ 이 칸이 가리는 것과 **가리지 못하는 것**

| | |
|---|---|
| 가린다 | **ggml 이 이 층을 호스트와 똑같이 계산하는가** |
| 가리지 못한다 | **llama.cpp 의 `qwen35` 경로가 옳은가** |

가중치가 합성이다. 연산 순서는 llama.cpp 에서 그대로 옮겼지만, 실제 가중치와
호스트 중간 텐서로 맞춰 보지 않았다. 후자는 호스트 `llama-eval-callback` 이
필요하고 그것은 llama.cpp 전체 빌드를 요구한다. **출력 마지막 줄에도 적어
둔다** — 통과를 과대 해석하지 않기 위해서다.

**262,144개짜리 순환 상태의 표본 1024개가 1개를 빼고 비트 일치**한다.
델타 규칙은 상태가 누적되므로 여기서 틀리면 뒤가 전부 틀린다 — 그 자리가 맞았다.

## 가장 값진 발견 — **`-ffp-contract` 를 양쪽에 고정해야 한다**

처음 돌렸을 때 `[5] ssm_conv` 가 **477/1024 불일치, 최대 66,993 ppb(6.7e-5)** 였다.
나머지가 94 ppb 인데 이것만 700배 나빴다. 통과 범위(1e-4) 안이었지만 넘기지 않고
증거를 뽑았다.

**① 먼저 상쇄인지 구분했다.** 비교 함수가 최대 오차 지점의 값을 찍게 했다.

```
최대 오차 지점 [194]: 얻음 0xba96ff69  골든 0xba970200
|골든| = 0.001152   |차| = 0.000000077
```

입력 항의 크기가 ~1 인데 결과가 0.00115 다. 즉 **절대오차 7.7e-8 은 float
반올림 한계(eps ≈ 1.2e-7) 수준**이고, 큰 상대오차는 순전히 상쇄다.

**② 그 1 ulp 가 어디서 왔는지 코드로 확인했다.**
`ggml_compute_forward_ssm_conv_f32`(`ggml-cpu/ops.cpp`)는 **intrinsic 이 아니라
평범한 스칼라 루프**다 — 주석까지 "not using `ggml_vec_dot_f32`, because its sum
is in double precision". 즉 커널 경로 차이가 아니다.

**③ 가설을 실험으로 확인했다.** gcc 와 clang 이 `sumf += a*b` 를 `fmadd` 로
묶는 기준이 다르다. 양쪽에 **`-ffp-contract=off`** 를 주자:

| | 전 | 후 |
|---|---|---|
| `ssm_conv` 표본 | 477/1024 다름, 66,993 ppb | **비트 일치** |
| `ssm_conv` 전체 CRC32 | 다름 | **일치** (`0xb799e3e4`) |

추정이 아니라 **확인된 원인**이다.

## 차이의 원인은 세 종류다 — 이제 구분된다

사다리 L3~L5a 에서 모은 것:

| 경로 | 결과 | 왜 |
|---|---|---|
| **SIMD·intrinsic** (내적·행렬곱·RMSNorm·SiLU) | **비트 일치** | 양쪽이 같은 intrinsic 을 쓴다. 컴파일러 재량이 없다 |
| **평범한 C 스칼라 루프** (`ssm_conv`) | 축약 정책에 좌우된다 → `-ffp-contract` 고정하면 **비트 일치** | `a*b+c` 를 `fmadd` 로 묶으면 중간 반올림이 한 번 줄어 1 ulp 갈린다 |
| **libm 호출** (`sin`·`cos`·`exp`·`sigmoid`) | **~1 ulp (94~344 ppb)** — 줄일 수 없다 | Apple libm 과 picolibc 의 구현이 다르다 |

그래서 계획서가 층마다 허용 오차를 다르게 둔 것이 옳다. 다만 **"비트 일치" 를
요구할 수 있는 범위가 생각보다 넓다** — 축약 정책만 맞추면 libm 을 지나는
곳만 빼고 전부 비트 일치다.

### 축약 정책은 **knob** 이다

```bash
# 정확성 사다리 (기본) — 재현성 우선
cmake -DLLM_GGML_FP_CONTRACT=off ...
# 성능 측정(L8) — FMA 를 쓴다
cmake -DLLM_GGML_FP_CONTRACT=fast ...   # 호스트는 LLM_FP_CONTRACT=fast
```

`off` 는 FMA 를 포기하므로 **생산 설정이 아니다.** L8 에서는 `fast` 로 다시 재고,
그때 허용 오차 안에 머무는지 L4·L5a 를 한 번 더 돌려야 한다.

추측하지 않았다. 전부 상류에서 읽어 옮겼다.

| 하위 | 출처 |
|---|---|
| L5a-1 `ggml_ssm_conv` 규약 | `ggml/src/ggml.c:5774-5791` |
| L5a-2 계수 | `src/models/qwen35.cpp:357-372` |

## 공개된 함정 셋이 실제로 그 자리에 있었다

**① `ssm_a` 는 이미 변환된 값이다.** 텐서 이름이 `SSM_A_NOSCAN` 이고 파일에
들어 있는 값이 **`-exp(A_log)`** 다(`qwen35.cpp:372` 의 주석 `-A_log.exp() *
softplus`). 즉 **항상 음수**다. 여기서 `A_log` 를 다시 `exp` 하면 틀리고,
양수를 넣으면 뒤의 `exp(gate)` 가 발산한다. 합성값도 음수로 뒀다.

**② `ssm_norm` 뒤는 `silu` 다 — `sigmoid` 가 아니다.**
`build_norm_gated`(`qwen35.cpp:252-261`)가 `build_norm(RMS)` 뒤에
`ggml_silu(gate)` 로 곱한다. 같은 파일 안에 `ggml_sigmoid` 를 쓰는 곳이
따로 있어(FFN 게이트) 헷갈리기 쉽다.

**③ 축 배치를 값보다 먼저 본다.** `[1]~[4]` 가 중간 텐서의 `ne[]` 를
호스트와 대조한다. 형태가 어긋나면 값 비교가 무의미하므로 순서가 중요하다.
확인된 모양:

```
q permute        [128,   1, 16, 1]
sum_rows(s*k)    [  1, 128, 16, 1]
k*d_t            [128, 128, 16, 1]
출력 o           [128,  16,  1, 1]   ← llama.cpp 의 [S_v, H_v, n_tokens, n_seqs]
```

## 메모리 — 층 1개의 순환 상태가 1 MiB 다

상태 텐서가 `[128,128,16]` = 262,144 f32 = **1 MiB**. 24층 중 DeltaNet 이
18층이므로 **순환 상태만 18 MiB**다. KV 캐시(어텐션 6층, 2K 토큰 24 MiB)와
합쳐 42 MiB — 128 MB 창 안이다.

그래프가 1 MiB 텐서를 여러 개 만들어 `ggml_init` 에 48 MiB 를 주고 아레나를
96 MiB 로 뒀다.

### **QEMU 와 숫자까지 전부 같다**

CRC 두 개(`0xb799e3e4` · `0xe01211cd`), 불일치 개수(2 · 1), 최대 상대오차
(94 ppb), 전체 요약(전부 0 ppb) — **하나도 다르지 않다.** L5b 와 같은 결론이다.

### 이 칸이 실기에서 추가로 확인한 것 — **메모리 압박**

| | 값 |
|---|---|
| RAM 사용 | **101,116 KB / 128 MB = 77.15%** |
| `ggml_init` 요청 | 48 MiB (아레나 96 MiB 의 절반) |
| 순환 상태 | `[128,128,16]` f32 = **1 MiB** (실기에서 실제로 할당·누적) |
| `MAX_XLAT_TABLES=24` | **충분했다** — sram 128 MiB + 모델 창 512 MiB + 96 MiB 아레나 동시 매핑 |

**262,144개짜리 순환 상태의 전체 합·절댓값 합이 0 ppb 로 일치한다.** 델타
규칙은 상태가 누적되므로 여기서 틀리면 뒤가 전부 틀린다 — 실기에서도 그
자리가 맞았다.

⚠ `[12]` 의 CRC 불일치는 `exp`/`sigmoid` 의 libm 1 ulp 가 상태에 섞인 것이고
**QEMU 에서도 같은 값**이다. 전체 요약이 그 영역의 상한을 준다.
