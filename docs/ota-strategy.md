# 펌웨어 갱신 경로 — 조사와 설계 (2026-11-06)

**문제.** 펌웨어를 바꿀 때마다 사람이 SD 카드를 빼서 맥에 꽂고 복사하고 다시
꽂고 전원을 넣어야 한다. 이것이 이 프로젝트에서 가장 비싼 비용이다.

**조사 결론 (실기 0회).** USB 로 SD 카드를 갱신하는 길은 지금 **막혀 있다.**
그러나 U-Boot 에 `fatwrite` 가 있어 **"Zephyr 가 RAM 에 받고 U-Boot 가 SD 에
쓰는"** 경로가 열릴 수 있다. 미지수는 하나다 — 재부팅 뒤 DRAM 보존.

---

## 1. 확인된 사실

### Zephyr 쪽 — SD 에 쓸 수단이 없다

- `drivers/sdhc/` 에 **Rockchip·dwcmshc·dw_mmc 드라이버가 없다** (검색 0건)
- 보드 DTS 와 인트리 `rk3568.dtsi` 에 **`sdmmc` 노드도 없다**
- 즉 드라이버를 처음부터 써야 하고, 그것은 dwc3 급 작업이다

### U-Boot 쪽 — 명령 목록 (`uboot.bin` 문자열 조사)

| 명령 | 있나 | 뜻 |
|---|---|---|
| `ums` (USB Mass Storage) | **없다** | SD 를 맥에 드라이브로 노출할 수 없다 |
| `fastboot` · `rockusb` · `dfu` | **없다** | **USB 로 파일을 넣는 수단이 하나도 없다** |
| `saveenv` | **없다** | 환경을 영구 저장할 수 없다 |
| `fatwrite` | **있다** ✅ | **U-Boot 는 SD 의 FAT 에 쓸 수 있다** |
| `fatrm` · `fatload` | 있다 ✅ | 파일 삭제·적재 |
| `itest` · `crc32` · `cmp` · `mw` | 있다 ✅ | RAM 검사·무결성 |
| `setexpr` | **없다** | 메모리 값을 변수로 읽을 수 없다 → **고정 크기**로 써야 한다 |

### 환경 기본값

```
bootdelay=0
baudrate=1500000
preboot=usb start; pci enum
stdout=serial,vidconsole
```

### ⚠ `bootdelay=0` — 1.5 Mbps 어댑터를 사도 소용없다

U-Boot 콘솔에 들어가려면 부팅 중 키를 눌러야 하는데 **대기가 0 초**다.
게다가 `saveenv` 가 없어 `bootdelay` 를 바꿔 저장할 수도 없다.

**즉 "1.5 Mbps 어댑터를 구해 U-Boot 콘솔에서 `ums` 를 쓴다" 는 두 번
막혔다** — 명령도 없고 콘솔에도 못 들어간다. 어댑터 구입이 이 문제를 풀지
못한다는 것을 **실기 0회**로 알아냈다.

### 메모리

DRAM 은 `0x00200000` ~ `0x80000000` (2 GB, 실기 검증). Zephyr 는
`0x40000000` + 1 MiB 만 쓰고 실제 사용은 324 KB 다. `PA_BITS=32`·`VA_BITS=32`
이므로 4 GB 전체가 주소 공간 안이다 — **1.9 GB 가 비어 있다.**

## 2. 설계 — Zephyr 가 RAM 에 받고 U-Boot 가 SD 에 쓴다

```
① Zephyr OTA 스레드가 USB CDC-ACM 으로 새 이미지를 받아 0x50000000 에 쌓는다
② 매직 "MORU" + 크기 + CRC32 헤더를 붙인다
③ moru ota apply → PSCI_SYSTEM_RESET 으로 재부팅
④ boot.scr 이 itest.l *0x50000000 -eq 0x4d4f5255 로 유효성 확인
⑤ fatwrite 로 zephyr.bin → zephyr.bin.old 백업, 받은 것 → zephyr.bin
⑥ 매직을 지우고(mw) go ${zentry}
   → 카드도 전원도 건드리지 않는다
```

`setexpr` 가 없어 크기를 변수로 읽을 수 없으므로 **고정 크기(256 KiB)로
`fatwrite`** 한다. 이미지보다 큰 뒤쪽은 Zephyr 의 `.bss` 영역에 들어가고
`arch_bss_zero()` 가 지우므로 무해하다.

### ⚠ 미지수 하나 — 재부팅 뒤 DRAM 이 보존되는가

PSCI `SYSTEM_RESET` 은 SoC 리셋이다. TF-A BL31 과 DDR 초기화가 메모리를
지우면 이 설계 전체가 무의미하다. **보장이 없고 실험으로만 알 수 있다.**

**가리는 실험 (실기 1회, `moru reboot` 시험과 같은 왕복):**

```
moru ota mark     0x50000000 에 매직 + 패턴을 쓴다
moru reboot       PSCI 재부팅
moru ota check    살아남았는지 읽어 본다
```

- 남으면 → 위 설계가 열린다 (**영속 OTA**)

## 3. 대안 — A/B 슬롯 RAM chain-load (영속 X, 개발 왕복 0)

DRAM 이 보존되지 않아도 **재부팅 없이** 새 펌웨어를 실행할 수 있다.

이미지는 `0x40000000` 에 위치 종속적으로 링크돼 있어(진입점 `0x40001084`)
다른 주소에 받으면 실행할 수 없고, `0x40000000` 로 복사하려면 자기가 도는
코드를 덮는다. → **두 번째 빌드를 `0x50000000` 에 링크한다.** 복사가 필요
없고 그냥 점프하면 된다.

```
슬롯 A  0x40000000  ← SD 카드가 부팅시킨 것 (황금 이미지, 손대지 않는다)
슬롯 B  0x50000000  ← OTA 로 받은 것
A 에서 B 를 받아 점프 → B 에서 A 를 받아 점프 → 번갈아
```

**벽돌이 되지 않는다.** SD 는 그대로이므로 점프가 실패하면 전원 재투입으로
원래 펌웨어가 돌아온다.

### 점프 전에 해야 할 것 (오늘 배운 것이 그대로 걸린다)

인터럽트 끄기 → USB 컨트롤러 정지 → dcache clean+invalidate → MMU off → 점프.

⚠ **`ARM64_BOOT_DISABLE_DCACHE` 는 EL2 부팅 경로의 코드라 EL1 점프에서는
돌지 않는다.** 캐시 정리를 빠뜨리면 `INIT_STACKS` 에서 겪은 그 무음을 다시
만난다 ([hardware-verified.md](hardware-verified.md) 의 EL2 데이터 캐시 절).
이번에는 원인을 알고 있다는 것이 차이다.

⚠ **EL 이 바뀐다.** U-Boot 는 EL2 에서 `go` 했지만 우리는 **EL1** 에서
점프한다. 새 이미지의 `switch_el` 이 `1:` 분기로 가 EL2 초기화를 건너뛴다.
동작할 것으로 보이지만 미검증이다.

## 4. 비용 비교

| 길 | 초기 비용 | 이후 왕복 | 벽돌 | 상태 |
|---|---|---|---|---|
| U-Boot `ums` | — | — | — | **막혔다** (명령 없음 + `bootdelay=0`) |
| **RAM→SD OTA** (§2) | 실기 1회(미지수) + 2~3회 | **카드 0 · 전원 0** | 없음 | 미지수 하나 |
| **A/B 슬롯** (§3) | 실기 3~5회 | 카드 0 · 전원 0 | 없음 | 가능 |
| SD 드라이버 | dwc3 급 | 0 | 없음 | 권하지 않는다 |
| 지금처럼 카드 교체 | — | 매번 | 없음 | 동작 중 |

§2 가 되면 §3 은 필요 없다. §2 의 미지수를 먼저 가린다.
